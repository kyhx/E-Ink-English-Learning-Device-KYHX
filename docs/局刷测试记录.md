# 4.2" SSD1619A 局刷测试记录

| 项目 | 内容 |
| --- | --- |
| 日期 | 2026-10-24 |
| 硬件 | ESP32-S3-N16R8 + 4.2" 单色 SSD1619A 400×300 + 驱动板 V1.5 |
| 固件 | 本工程 `main.c`，`EPD_PARTIAL_TEST=1` |
| 测试接口 | `epd_display_area_ex(fb, x, y, w, h, ctrl2, timeout_ms)` |
| 测试区域 | `x=272, y=10, w=120, h=40`（8 对齐） |
| 基线 | 整帧 `0xC7` 全刷 |
| 串口 | 115200，记录每种模式的 BUSY 总时间 |

## 1. 测试方法

1. 初始化面板，先整帧刷新一张固定测试底图（`0xC7`）。
2. 在右上角 120×40 区域交替写入黑/白/棋盘格。
3. 对每种 `0x22` 值调用一次区域刷新，记录从开始到 BUSY 释放的时间。
4. 超时设为 10 秒；若模式不产生 BUSY，会很快返回。
5. 串口打印 `TEST mode=0x..: ok=.., total=.. ms`。

## 2. 测试结果

| `0x22` | 含义 | BUSY 总时间 | 结论 |
| --- | --- | --- | --- |
| 基线 | 整帧 `0xC7` | 4124 ms | 全刷基线 |
| `0xC7` | clock+analog+display mode1 | 4096 ms | 全刷 |
| `0xCF` | clock+analog+display mode2 | 4096 ms | 全刷 |
| `0x47` | analog+display mode1 | 4096 ms | 全刷 |
| `0x4F` | analog+display mode2 | 4096 ms | 全刷 |
| `0x44` | analog+display mode1（analog 保持） | 4016 ms | 全刷 |
| `0x4C` | analog+display mode2（analog 保持） | 4016 ms | 全刷 |
| `0x04` | display mode1 only | 3926 ms | 全刷 |
| `0x0C` | display mode2 only | 3926 ms | 全刷 |
| `0xFF` | SSD1683-style partial | 4101 ms | 全刷 |
| `0xFF` + RED 基线 | BW=新帧，RED=上一帧 | 4159 ms | 全刷 |

> 所有模式都在 3.9–4.1 秒，且与整帧基线同一量级；没有任何一种接近局刷常见的 0.3–1.5 秒。

### 2.1 颜色判定：这块是单色屏

局刷测试前先用 `epd_display_bw_red()` 做了 RED 平面测试：

- `0x24` 写 BW，`0x26` 写 RED，`0x21=0x00`（两个平面都正常使用）；
- 屏幕三条竖带：白 | 黑 | 红；
- 结果：**第三块仍然是白色，没有红色**。

结合社区记录（SSD1619 使用 OTP 查找表，可显示单色），确认 **HINK-E042A13-A0 是单色屏**。
所以上面的局刷测试是在单色面板上做的：**单色并不代表一定能局刷**，关键还是 OTP 里有没有 partial LUT。

### 2.2 强行套用 SSD1683 fast-partial LUT

参考仓库：[miklav/SSD1683-fast-partial-lut](https://github.com/miklav/SSD1683-fast-partial-lut)（GPL-3.0，目标 GDEY042T81/SSD1683）。

按原序列强行发送：

- `0x0C` 软启动：`8B 9C A4 0F`
- `0x32` + 227 字节自定义 LUT（5 组 × 42 字节，`lut[224]=0x02`）
- `0x3F=0x22`、`0x03=0x17`、`0x04=0x41 A8 32`、`0x2C=0x30`
- `0x21 00 00`、`0x22=0xDC`、`0x20`

结果：

| 项目 | 结果 |
| --- | --- |
| BUSY 时间 | **1936 ms**（比原 4.1 秒短一半） |
| 画面 | **整个屏幕闪一下再更新** |
| 是否只刷 120×40 区域 | **否**，仍是全屏刷新 |
| 结论 | 自定义 LUT 让“全刷”变快，但不是 partial |

> 该 LUT/序列是 GPL-3.0 派生代码，且会改写电压/LUT 寄存器，仅用于本次本地验证；没有并入工程发布版。

### 2.3 OSHWHub GaAs 项目的 70 字节 LUT

参考项目：[SSD1619~手冲灰阶墨水屏牌子~](https://oshwhub.com/GaAs/mo-shui-ping-pai-zi)（MIT，STM32F401，SSD1619A 4.2" 400×300）。

它提供的是**同款面板的 70 字节 LUT**（完整 LUT + 8/16 级灰度 LUT），不是 partial 方案。移植其初始化/电压/扫描方向后实测：

| LUT | BUSY 时间 | 画面 | 结论 |
| --- | --- | --- | --- |
| Full LUT（4 相） | **2085 ms** | 清晰、黑白正确 | **快速全刷**，比 OTP 4.1 秒快一倍 |
| GS LUT（单相，RP0=8） | **450 ms** | 很淡、残影严重 | 只是灰度单相波形，不能当完整刷新 |

两者仍然是**整屏扫描/整屏闪烁**，不是只刷变化区域的 partial。

> 该项目 Full/GS LUT 的实验代码已在清理时移除；工程只保留后续验证可用的 partial LUT。

### 2.4 EPaperDrive partial LUT：局刷成功

参考项目：[某价签改装极简墨水屏开发板 手改灰度](https://oshwhub.com/shilihualang/han-jia-qian-gai-zhuang-ji-jian-kai-fa-ban) / [HalfSweetStudio/EPaperDrive](https://github.com/HalfSweetStudio/EPaperDrive)。屏幕丝印正是 **HINK-E042A13-A0**。

关键：它提供了 OTP 里没有的 **70 字节 partial LUT**（`LUTDefault_part_opm42`）和 `EPD_init_Part()` / `EPD_Dis_Part()` 流程。

本工程按该流程实现：

```text
HW reset
0x74/0x7E、0x01、0x0C、0x3A=0x21、0x3B=0x06、0x3C=0x03
0x11=0x03、0x2C=0x00、0x37=00 00 00 00 80
0x21=0x40、0x22=0xC7
0x21=0x00 + 0x32 + 70 字节 partial LUT
整屏写 0x24 + 0x20（底图）
局部窗口 0x44/0x45/0x4E/0x4F + 0x24 + 0x20（局刷）
```

实测：

| 步骤 | 时间 | 结果 |
| --- | --- | --- |
| 整屏底图 | **700 ms** | 底图正确 |
| 120×40 区域更新 | **670 ms** | **只有右上角棋盘格变化，没有全屏闪** |

**结论：这块 HINK SSD1619A 可以实现真正的局部刷新，但必须使用自定义 partial LUT，不能只靠 OTP。** 之前“这块屏不能局刷”的结论只适用于“只用 OTP/标准 `0x22`”的情况。

> 注意：EPaperDrive 是 **AGPL-3.0**。上述 LUT/序列仅用于本地验证；如果要发布/商用，需要遵守 AGPL-3.0，或联系作者取得授权，或从 datasheet 独立重写 partial LUT。

### 2.5 30 次连续局刷 + 清洁周期

在 2.4 的 partial 模式上连续刷新右上角 120×40 区域 30 次，图案按黑/白/棋盘/反棋盘交替：

| 项目 | 结果 |
| --- | --- |
| 单次区域更新 | **680 ms**，30 次稳定 |
| 30 次后残影 | **轻微**，底图基本不变 |
| 只重画一次底图（709 ms） | 仍有轻微残影 |
| 全白 → 全黑 → 底图（3 × 709 ms） | **完全干净，和初始底图一致** |

**结论：partial LUT 连续局刷会累积轻微残影；一次底图重画不够，需要“全白 → 全黑 → 底图”的清洁周期才能完全复位。**
建议每 **20–30 次局刷**做一次清洁周期（约 2.1 秒），或按残影程度调整；对残影敏感的场景可每 10 次清洁一次。

### 2.6 50 个单词居中 / 1 秒切换

用 partial 模式做单词卡演示：

- 布局 320×120，最终用 **70 行带状窗口（95..164）**：序号 `NN/50`（2 倍字体）+ 单词（4 倍字体）；
- 底图只画一次：标题 “50 WORDS”、外框、页脚；
- 每个词刷新 **346 ms**，刷新后停留 **1 秒**（约 1.35 s/词）；
- 第 25 个词后做一次清洁周期，第 50 个词后再清洁并显示 DONE。

实测日志（节选）：

```text
WORDS init: base=700 ms, word1=346 ms
WORD 02/50 book : 346 ms
...
WORD 25/50 zero : 346 ms
WORDS clean MID white/black/base: 710/709/710 ms
WORD 26/50 bird : 346 ms
...
WORD 50/50 zoom : 346 ms
WORDS clean END white/black/base: 709/709/710 ms
```

视觉确认：**单词/序号居中清晰、字号合适；25 次内有轻微残影，清洁后恢复；每个词停留 1 秒符合预期。**

> 带状内必须写整条 400px 宽：只写 128px 时横带左右会闪；整宽写入后未变化像素不驱动，横带不闪。详见 2.9。

### 2.7 完全 EPaperDrive 式窗口验证

按 `EPD_Dis_Part` 原语义实现：

- 整帧 buffer + offset 取窗口数据；
- x/y 交换 + Y 反向窗口；
- `0x11=0x01`（Y 递减）；
- 数据行按 y1 → y0 反向取；
- `0x20` 刷新后补写一次基线。

结果：

| 项目 | 结果 |
| --- | --- |
| 单词/序号 | **方向正确、位置正确** |
| 单次刷新 | **684 ms** |
| 窗口外侧 | **仍然整屏闪** |

结论：坐标和数据布局已经与 EPaperDrive 对齐；“窗口外闪”来自这套 partial LUT 的波形/整屏 gate 扫描，不是窗口坐标错误。要完全静默局刷，仍需要真正的 partial 波形或换屏。

### 2.8 为什么 400×300 反而不闪

这套 partial LUT 的相位表：

```text
LUT0 BB = 0x00  黑->黑，不驱动
LUT1 BW = 0x82  黑->白，驱动
LUT2 WB = 0x50  白->黑，驱动
LUT3 WW = 0x00  白->白，不驱动
LUT4 VCOM = 0x00
```

它不是“整屏先闪白再闪黑”的全刷波形，而是**只驱动发生变化的像素**：

- 写整帧 400×300 时，每个像素的 old/new 状态都完整；
- 没变化的像素走 WW/BB，相位为 0，不驱动；
- 只有文字笔画走 BW/WB，被短脉冲翻转；
- 所以视觉上**没有整屏闪**，只有文字在变。

窗口缩小到 128×70 时，窗口外的像素没有新的 old/new 数据，但控制器仍然扫描整屏 gate；窗口边界和残留状态会导致窗口外闪/残影。

清洁周期“全白→全黑”会让所有像素都发生转换，所以那三次是**应该看到整屏闪**的。

**结论：当前方案是“整帧数据 + transition-only LUT 的快速无闪刷新”，不是窗口 partial。** 它用整帧数据换取每个像素状态一致，从而避免整屏闪。

### 2.9 MUX + gate start：带状真局刷（最终方案）

datasheet 里没有“partial window”专用位；`0x22` 只组合 clock/analog/display/LUT，`0x44/0x45` 只限制 RAM 写入窗口，显示阶段默认扫全部 gate。
但 SSD1619A 支持：

- `0x01` Driver Output Control：设置 MUX（16..300）
- `0x0F` Gate Scan Start Position：设置起始 gate（0..299）

利用这两个寄存器，把扫描限制在 **70 行**；同时**整条 400px 宽都写入数据**：

```text
MUX = 69（70 行）
gate start = 95
RAM Y = 95..164
RAM X = 0..399（整宽）
写入 400×70 = 3500 字节
```

实测：

| 项目 | 结果 |
| --- | --- |
| 单次刷新 | **346 ms** |
| 单词/序号 | 位置、内容正确 |
| 带状区域外 | **始终完全不动** |
| 带状区域 | **横带不闪，只有单词/序号变化** |
| 50 词连续 | 稳定，每词 346 ms |
| 残影 | 轻微；全白→全黑→底图清洁后完全恢复 |

关键：**带状内必须写整条 400px 宽**。只写 128px 时，横带左右两侧没有新数据，LUT 仍会驱动/闪；整宽写入后，未变化像素走 WW/BB 不驱动，所以横带不闪。

**结论：SSD1619A 没有“任意 2D 窗口局刷”，但可以用 MUX + gate start 实现“70 行横向带状真局刷”：只扫 70 行，带状外完全不动，横带内只有文字变化、无可见闪。**
X 方向仍是全宽，但不是“全宽都闪”，所以视觉和 gate 扫描都是真正的局部刷新。

> 注意：这是利用 `0x01/0x0F` 的扫描范围限制，datasheet 没有把它命名为 partial update；长期可靠性、MUX 切换次数、温度影响仍需验证。

## 3. 结论

1. **SSD1619A 没有“任意 2D 窗口局刷”专用位**：`0x22` 只组合 clock/analog/display/LUT，`0x21` 只选 RAM 内容，`0x44/0x45` 只限制 RAM 写入窗口；默认显示阶段扫全部 gate。
2. **可以用 MUX + gate start 做“横向带状真局刷”**：MUX=69、gate start=95、RAM Y=95..164、整宽写入，只扫 70 行，带状外完全不动。
3. **带状局刷实测 346 ms/词**，50 词连续稳定；横带不闪，只有文字变化；残影轻微，清洁后恢复。
4. **它不是任意矩形窗口**：X 方向仍全宽，但整宽数据保证未变化像素不驱动；Y 方向是真正的局部扫描。
5. **全帧 transition-only 仍可用**：400×300 全帧约 739 ms，无可见闪；带状方案更快、更省 gate 扫描。
6. **当前固件使用 `epd_band_update()` 带状局刷**；`epd_display_area()` 仍是 OTP 全刷路径。

## 4. 下一步可选方案

| 方案 | 需要的东西 | 成本 | 建议 |
| --- | --- | --- | --- |
| A. 采用 EPaperDrive partial LUT | 遵守 AGPL-3.0 或取得授权 | 低-中 | **已实测可用**，优先做连续刷新/残影测试 |
| B. 用 MUX + gate start 带状局刷 | 已验证；需长期可靠性测试 | 低 | **当前方案**，346 ms |
| C. 从 datasheet 独立重写 partial LUT | 波形参数 + 测试 | 高 | 不想受 AGPL 约束时做 |
| D. 换 2.9" 支持真窗口 partial 的单色屏 | 新屏 + 驱动适配 | 中 | 需要任意矩形窗口时的对照方案 |

## 5. 复现方法

```bash
idf.py build
idf.py -p COM4 flash monitor
```
