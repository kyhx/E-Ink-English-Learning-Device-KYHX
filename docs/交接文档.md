## 0. 一句话现状

**HINK-E042A13-A0（4.2" 单色 SSD1619A）已经能用 MUX + gate start 做 70 行横向带状真局刷：346 ms/词，带状外完全不动；50 个单词居中、每词停留 1 秒、每 25 词清洁一次，跑完显示 DONE 并深睡。它不是任意 2D 窗口，X 方向仍全宽，但横带不闪。**

## 4. 当前刷新方案（最重要）

### 4.1 初始化序列

`epd_partial_init()` 做：

```text
硬件复位
0x74 0x54
0x7E 0x3B
0x01 0x2B 0x01 0x00
0x0C 0x8B 0x9C 0xD6 0x0F
0x3A 0x21
0x3B 0x06
0x3C 0x03
0x11 0x03
0x2C 0x00
0x37 0x00 0x00 0x00 0x00 0x80
0x21 0x40
0x22 0xC7
0x21 0x00
0x32 + 70 字节 partial LUT
```

### 4.2 单次刷新（当前：带状局刷）

`epd_band_update()` 当前做：

```text
0x22 0x80 + 0x20       重新开时钟
0x22 0xC7              设置刷新序列
0x01 0x45 0x00 0x00    MUX=69（70 行）
0x0F 0x5F 0x00         gate start=95
0x11 0x03              数据方向
0x44 0x00 0x31         X 窗口 0..399（整宽）
0x45 0x5F 0x00 0xA4 0x00 Y 窗口 95..164
0x4E 0x00
0x4F 0x5F 0x00
0x24 + 3500 字节        写 400×70 整宽
0x20                    触发
等待 BUSY（约 346 ms）
```

下一次全屏/带状操作会自行设置 MUX；当前不在带状刷新后额外做 0x80+0x20 恢复。

### 4.3 清洁周期

`clean_cycle()`：

```text
全白  -> 0x24 + 0x20，约 709 ms
全黑  -> 0x24 + 0x20，约 709 ms
底图  -> 0x24 + 0x20，约 709 ms
重载 partial LUT
```

当前在 **START / 第 25 词 / 第 50 词** 各做一次。
建议产品中改成 **每 20–30 次局刷**或残影明显时再做，不要每次开机都做。

### 4.4 实测时间

| 项目 | 时间 |
| --- | --- |
| 单次带状局刷（70 行） | **346 ms**（早期 351 ms） |
| 单词停留 | 1 s |
| 每词节奏 | **约 1.34 s** |
| 清洁一次 | 3 × 709 ms ≈ 2.1 s |
| 50 词总时长 | 约 67 s + 清洁，约 74 s |

### 4.5 为什么带状刷新不闪 / 外部不动

这套 LUT 是 transition-only：

```text
LUT0 BB = 0x00   黑->黑，不驱动
LUT1 BW = 0x82   黑->白，驱动
LUT2 WB = 0x50   白->黑，驱动
LUT3 WW = 0x00   白->白，不驱动
LUT4 VCOM = 0x00
```

带状刷新时：

```text
0x01 = MUX 69（70 行）
0x0F = gate start 95
0x45 = RAM Y 95..164
0x44 = RAM X 136..263
```

- 只扫描 95..164 这 70 行，带状外的 gate 不扫描，所以外部完全不动；
- 带状内仍写 128 px 宽的数据，未变化像素不驱动；
- X 方向没有源窗口，但整条 400px 都写入数据，未变化像素不驱动，所以横带不闪；
- 这是 **Y 方向的真局部扫描**，不是任意 2D 窗口。

### 4.6 关键结论

- 当前是 **MUX + gate start 的横向带状真局刷**：只扫 70 行，带状外完全不动；
- 单次 346 ms/词，50 词稳定；
- 不是任意矩形窗口：X 方向仍全宽，但整宽数据写入后横带不闪；
- 相对 OTP 全刷 4–6 s，刷新时间和 gate 扫描量都大幅下降；
- 可以写“**带状局部刷新降低刷新功耗**”，但不要写“任意窗口局刷”。

## 5. 已做过的实验与结论

| 方案 | 时间 | 结果 |
| --- | --- | --- |
| OTP 全刷 `0xC7` | 4–6 s | 稳定，全屏闪 |
| 原 OTP + 区域写 RAM | 4–6 s | 只省 SPI，面板仍全刷 |
| SSD1683 227B fast LUT（强行） | 1936 ms | 全屏闪，不是 partial；GPL，已移除 |
| GaAs Full LUT | 2085 ms | 清晰全刷；代码已清理移除 |
| GaAs GS LUT | 450 ms | 很淡/残影；已移除 |
| EPaperDrive 128×70 窗口 | 684 ms | 单词正确，框外整屏闪 |
| 400×300 全帧 transition-only | 739 ms | 无可见闪，单词正常 |
| **MUX + gate start 70 行带状（当前）** | **346 ms** | **带状外完全不动、横带不闪，单词正常** |
| 连续 50 次带状 | 346 ms/次 | 轻微残影，清洁可恢复 |
| 清洁周期 | 3×709 ms | 完全恢复干净 |

## 6. 已知问题 / 风险

### 6.1 许可证（高优先级）

- 当前 `epd_lut_partial.h` 的 70 字节 LUT 和初始化/刷新序列来自 **HalfSweetStudio/EPaperDrive**，该库是 **AGPL-3.0**。
- 本工程 README 原写的是 MIT；**两者不兼容**。
- 如果要发布/商用/开源，必须三选一：
  1. 整个项目按 AGPL-3.0 开源；
  2. 联系作者取得授权；
  3. 从 datasheet 独立重写 partial LUT/序列。
- 仅本地论文实验可暂时使用，但要在论文/文档中注明来源与许可证。

### 6.2 是“带状真局刷”，不是任意 2D 窗口

- 通过 MUX + gate start 只扫 70 行，Y 方向是真局部扫描；
- X 方向仍全宽，但整宽数据写入后横带不闪；
- 不是任意矩形窗口；不要宣称“任意位置/任意大小窗口局刷”；
- `0x01/0x0F` 的这种方式 datasheet 未命名为 partial update，长期可靠性需验证。

### 6.3 功耗未实测

- 当前 CPU 240 MHz、PM 关闭、tickless 关闭；
- 每词后 `vTaskDelay(1000)` 是 **240 MHz 空转 1 秒**；
- 开机清洁固定 2.1 s；
- 没有电流/能量实测数据；
- 相对 OTP 全刷/400×300 全帧，带状方案已减少 gate 扫描量；但仍需实测后才能量化“降低功耗”。

### 6.4 残影/寿命

- 连续局刷会累积轻微残影；
- 当前每 25 词清洁一次；
- 长期（1000+ 次）、温度变化、面板批次差异未验证；
- 建议每 20–30 次清洁，并做 100–500 次循环测试。

### 6.5 代码遗留

- `epd_epd_dis_part()` 是可选实验接口，当前未使用；
- 可保留用于对照，也可在最终版删除；
- `epd_display_area()` 仍是 OTP 全刷路径，不是局刷。

### 9.2 常见问题

| --- | --- |
| 全白/无显示 | 检查 CS 是否整段拉低、0x21 是否只发 1 字节、0xB1/时钟 |

| 刷新后写 RAM 无效 | 0xC7 后时钟关闭，需要 0x22=0x80 + 0x20 |
| 颜色发红/三色 | 本屏是单色；不要按三色初始化 |
