## 1. 项目概述

### 1.1 背景

纸质单词书不便于随时复习；手机 App 依赖屏幕，长时间使用容易造成视觉疲劳。电子墨水屏具有双稳态、低功耗、接近纸张的显示观感，适合做便携式单词学习机。与此同时，ESP32-S3 等带 PSRAM 的 MCU 已能在本地完成小型神经网络的 int8 推理，使“发音跟读评价”不依赖网络成为可能。

### 1.2 目标

设计并实现一款便携式英语单词学习机，形成“**采集 → 评测 → 呈现 → 同步**”闭环：

1. 内置不少于 50 个词条的自建词库（本方案按 100 词设计，最低 50 词）。
2. 采用分级复习（Leitner 盒）安排每日学习量。
3. 5 个按键完成单词切换、发音播放、跟读录音、结果查看、记录同步。
4. 采集不少于 200 条真实跟读语音（本方案按 300–500 条），人工标注“正确/错误”。
5. 提取 log-Mel 特征，训练轻量二分类器，量化后在 ESP32-S3 本地推理。
6. 实现基于基频 F0 的规则法作为对照，比较两种方法在准确率、评分一致性、推理耗时上的差异。
7. 墨水屏单词卡界面 + 区域写 RAM 策略；实测刷新耗时与功耗。
8. 学习记录通过 Wi-Fi SoftAP + HTTP 同步到手机/上位机。
9. 实测待机、录音、推理三种状态电流，记录推理耗时与刷新耗时。

### 1.3 范围与边界

- 发音评价仅做“跟读是否正确”的二分类辅助判断，**不作为语言能力评定**。
- 不实现离线 TTS；单词发音使用预录音频。
- 不实现手机原生 App；同步使用手机/PC 浏览器。
- 4.2" 屏没有 OTP partial；但通过 MUX + gate start + 自定义 partial LUT，已实现 70 行带状真局刷（346 ms）。它不是任意 2D 窗口，X 仍全宽，论文中如实说明。

| F2 | 分级复习 | Leitner 盒，按到期日生成每日队列；答对升级、答错降级 | 高 |

| F12 | 统计 | 连续天数、正确率、今日进度 | 中 |
| F13 | 设置 | 每日新词数、音量、同步开关 | 中 |

### 2.2 非功能需求

| 类别 | 指标 | 目标 |
| --- | --- | --- |
| 显示 | 分辨率/颜色 | 400×300，1bpp 黑白 |
| 刷新 | 全刷耗时 | ≤6 秒（当前实测约 5.6 秒） |
| 刷新 | 区域写 RAM | x、w 为 8 的倍数；仍触发全刷 |
| 续航 | 深睡电流 | 目标 <100µA（整机，实测为准） |
| 续航 | 单次学习能耗 | 以“刷新次数 × 单次刷新能量”估算 |
| 推理 | 单次耗时 | 目标 <200ms（含预处理） |
| 模型 | 准确率 | 目标 ≥75%，以说话人独立测试为准 |
| 模型 | 模型大小 | <100KB（int8） |
| 同步 | 成功率 | ≥95%（同一局域网/热点） |
| 可靠 | 掉电 | 学习记录写入 NVS，掉电不丢已确认记录 |
| 安全 | 免责声明 | 界面和文档均注明“仅作学习参考” |

### 2.3 约束

- 4.2" SSD1619A 无 OTP partial；用自定义 LUT + MUX/gate start 可做 70 行带状真局刷，约 346 ms。
- 200 条样本偏少：必须按说话人划分，报告置信区间，避免夸大。
- ESP32-S3 无 DAC：音频播放必须用 I2S 功放。
- 单词音标含 IPA：需要额外点阵字形，不能用现有 5×7 ASCII 字体完整显示。

### 4.2 显示

- 型号：4.2" 单色，SSD1619A，400×300，1bpp。
- 接口：SPI2，Mode 0，4MHz（可尝试 8–10MHz，需实测稳定性）。
- 引脚：见 4.7。
- 供电：3.3V；刷新瞬态电流较大，电源需留余量。
- 现有驱动能力：
  - `epd_display(fb)`：整帧 15,000 字节。
  - `epd_display_area(fb, x, y, w, h)`：区域写 RAM，`x`/`w` 必须为 8 的倍数；仍触发 `0xC7` 全刷。
  - `epd_fb_*`：像素、线、矩形、5×7 文本。
  - `epd_deep_sleep()`：深睡保持画面。
- **重要限制**：参考驱动 GxEPD2 GDEH042Z96 标记 `hasPartialUpdate = false`，但那不代表硬件完全不能；实测用 MUX + gate start 可做 70 行带状真局刷（346 ms），只是不是任意 2D 窗口。

### 4.3 音频

#### 麦克风 INMP441（I2S RX）

- 供电 3.3V，L/R 接地选择左声道。
- 采样：16kHz，16bit，单声道；INMP441 输出 24bit，取高 16bit。
- DMA：8 个 256 字节缓冲；录音 2 秒缓冲约 64KB，放 PSRAM。
- 录音流程：启动 I2S → 采集 2s → 停止 → 去直流 → VAD/端点检测 → 特征提取。

#### 功放 MAX98357A（I2S TX）

- 供电 3.3V 或 5V（按模块），喇叭 4Ω 3W。
- 采样：16kHz，16bit，单声道；支持 WAV/ADPCM 解码播放。
- `SD` 关断脚：空闲拉低，播放时拉高，降低静态功耗。
- 播放与录音分时复用，避免回声；如要同时，需要回声消除，暂不做。

### 4.4 按键

5 个按键，低电平有效，内部上拉，外部 100nF 消抖；软件 20ms 消抖 + 短按/长按。

| 按键 | 功能 | 长按 |
| --- | --- | --- |
| KEY_PREV | 上一个单词/上移 | 返回首页 |
| KEY_NEXT | 下一个单词/下移 | 进入统计 |
| KEY_PLAY | 播放发音 | 重播 |
| KEY_RECORD | 开始/停止录音 | 重新录音 |
| KEY_SYNC | 同步 | 进入设置/配网 |

### 4.5 存储

16MB Flash 分区建议：

| Name | Type | SubType | Offset | Size | 用途 |
| --- | --- | --- | --- | --- | --- |
| nvs | data | nvs | 0x9000 | 0x5000 | 设置、复习队列、记录索引 |
| phy_init | data | phy | 0xE000 | 0x1000 | RF 校准 |
| factory | app | factory | 0x10000 | 3M | 固件 |
| storage | data | littlefs | 0x310000 | 8M | 词库、音频、记录导出 |

- 词库：`/words/words.json`。
- 音频：`/audio/0001.wav` 或 `.adpcm`；100 词 × 1.5s × 16kHz × 2B ≈ 4.8MB，8MB 分区足够；ADPCM 可减半。
- 记录：NVS 环形缓冲（如 512 条），同步后标记；也可落盘 CSV。

### 4.6 电源与测量

- 3.7V 锂电 → TP4056 充电/保护 → 3.3V 升降压 → 主控/屏/音频。
- 音频功放瞬态电流大，3.3V 轨需 1A 以上能力并加 470µF 以上 Bulk 电容。
- INA219 串在电池或 3.3V 轨，I²C 读取总线电压/电流/功率。
- USB 电流表用于整机平均电流/充电电流。
- 测量点：深睡、空闲、录音、推理、全刷、区域写+全刷、Wi-Fi 同步。

## 5. 软件设计

### 5.1 显示与页面管理

- 15,000 字节 1bpp 全帧缓冲；页面管理器只维护一个 `epd_fb`。
- 页面：首页、单词卡、跟读结果、统计、设置、同步。
- 字体：
  - 5×7 ASCII：小标签/状态。
  - 16×16、24×32 点阵：单词、释义；由 TTF/点阵字库离线生成 C 数组。
  - IPA 子集：`ˈ ˌ ː ə ɪ ʊ æ ɑ ʌ ɔ ɜ ɚ ɝ e ɛ o ɒ ʊ aɪ aʊ eɪ oʊ ɔɪ ɪə eə ʊə p b t d k g f v θ ð s z ʃ ʒ h tʃ dʒ m n ŋ l r j w` 等；只生成词库实际用到的字符，避免全字库。
- 刷新策略：
  1. 页面渲染到 `epd_fb`。
  2. 计算脏矩形（可选），只把脏区域写入 RAM；`x`/`w` 8 对齐。
  3. 调用 `epd_display_area()` 触发全刷（5.6s）。
  4. 记录 SPI 写入时间、面板刷新时间；论文中分开报告。
- 不做运行时 LVGL；如后续需要复杂 UI，用 LVGL 离线设计导出 1bpp 静态帧。

### 5.2 词库与分级复习

词条结构（示意）：

```c
typedef struct {
    uint16_t id;
    char word[32];
    char phonetic[48];     /* IPA，UTF-8 */
    char meaning[64];      /* 中文释义，UTF-8 点阵渲染需另做字库 */
    char example[96];
    uint32_t audio_off;    /* LittleFS 文件偏移或索引 */
    uint8_t level;         /* Leitner 0..5 */
    uint16_t correct;
    uint16_t wrong;
    uint32_t next_due;     /* UTC 天数 */
} word_t;
```

> 中文释义需要中文点阵字库；若不想做中文全字库，可用英文释义/图片，或只生成词库用到的汉字子集（推荐，几十个字，体积很小）。

Leitner 间隔：`1, 2, 4, 7, 15, 30` 天；答对 `level++`，答错 `level=0`；每日队列 = 到期复习 + 新词（默认 10 个）。时间来源：Wi-Fi 同步时 SNTP 校时；无网络时用 RTC/开机天数近似，同步时校正。

### 5.3 音频链路

```text
播放：LittleFS WAV/ADPCM → 解码 → I2S1 → MAX98357A → 喇叭
录音：INMP441 → I2S0 → PSRAM 缓冲 → 去直流/VAD → 16kHz 单声道
评测：录音 → log-Mel(40×64) → int8 模型 → 正确/错误 + 置信度
对照：录音 → YIN F0 → DTW vs 参考 → 分数 + 正确/错误
```

- VAD：短时能量 + 过零率；去掉首尾静音，保留 100ms 余量。
- 录音 2 秒；若有效语音 <0.4 秒，提示“未检测到语音”。
- 播放时关闭麦克风输入，避免啸叫。

### 5.4 无线同步

- 设备作为 SoftAP：`EPD-Word-XXXX`，WPA2 密码；IP `192.168.4.1`。
- HTTP 服务（`esp_http_server`）：
  - `GET /`：简单 HTML 仪表盘。
  - `GET /api/records.json`：JSON 记录。
  - `GET /api/records.csv`：CSV 记录。
  - `POST /api/ack`：标记已同步。
  - `POST /api/words`：可选，上传新词库。
- 记录 JSON 示例：

```json
{
  "device": "EPD-Word-0001",
  "fw": "0.1.0",
  "records": [
    {"ts": 1760000000, "word_id": 12, "result": 1, "score": 82,
     "method": "cnn", "latency_ms": 41}
  ]
}
```

- 同步流程：按键 → 开 Wi-Fi/HTTP → 手机/PC 连接 → 浏览器下载 → 关闭 Wi-Fi。
- 功耗：Wi-Fi 仅按需开启，3 分钟无操作自动关闭。

### 5.5 低功耗状态机

| 状态 | 外设 | 唤醒源 | 目标电流 |
| --- | --- | --- | --- |
| DEEP_SLEEP | EPD 深睡；Wi-Fi/音频/ADC 关闭 | 5 按键（EXT1） | <100µA |
| LIGHT_SLEEP | EPD 保持；CPU 轻睡 | 按键/定时器 | 0.1–2mA |
| IDLE | CPU 240MHz，屏静态 | 按键 | 20–50mA |
| RECORDING | I2S0 + PSRAM | 录音键 | 40–80mA |
| INFERENCE | CPU + PSRAM | 自动 | 40–80mA |
| REFRESH | SPI + 面板升压 | 自动 | 20–40mA × 5.6s |
| WIFI_SYNC | Wi-Fi + HTTP | 同步键 | 100–200mA |

- 每次刷新完成后调用 `epd_deep_sleep()`；按键用 `esp_sleep_enable_ext1_wakeup()`。
- 音频功放 `SD` 空闲拉低；麦克风可断电或用 I2S 停止时钟。
- 记录能量：`E = Σ(V × I × t)`，论文中给 mJ/次。

## 6. 边缘 AI 设计

### 6.1 数据集

| 项目 | 计划 |
| --- | --- |
| 样本数 | 300–500 条（最低 200） |
| 说话人 | ≥5 人，男女均衡，尽量覆盖不同口音 |
| 词条 | 50–100 个词，每词多说话人/多遍 |
| 类别 | 正确/错误，尽量均衡 |
| 标注 | 2 人独立标注 + 第三人裁决；报告 Cohen's kappa |
| 录音 | 16kHz/16bit 单声道，安静环境，麦克风距离固定 |
| 划分 | **按说话人** 5 折交叉验证；测试集说话人不参与训练 |
| 增强 | 时间偏移、增益、加噪、轻微变速；只用于训练 |

标注标准（示例）：

- 正确：音素基本准确、重音/节奏可接受、无明显吞音/加音。
- 错误：明显音素替换、吞音、加音、重音错误到影响识别。
- 边界样本：两人分歧且第三人无法统一 → 剔除或标为“边界”，不参与二分类。

### 6.2 预处理

1. 去直流、预加重（可选）。
2. VAD/端点检测，保留 100ms 前后余量。
3. 重采样到 16kHz；固定 2 秒（不足补零，超过截断）。
4. log-Mel：40 个 Mel 滤波器，25ms 窗，10ms 移，得到 40×64。
5. 每条样本做均值/方差归一化；int8 量化时保存 scale/zero-point。

### 6.3 模型

| 层 | 配置 | 输出 |
| --- | --- | --- |
| Input | 40×64×1 | — |
| Conv1 + BN + ReLU | 3×3, 16 | 40×64×16 |
| MaxPool | 2×2 | 20×32×16 |
| Conv2 + BN + ReLU | 3×3, 32 | 20×32×32 |
| MaxPool | 2×2 | 10×16×32 |
| Conv3 + BN + ReLU | 3×3, 64 | 10×16×64 |
| GlobalAvgPool | — | 64 |
| Dropout | 0.3 | 64 |
| Dense | 64→2 | 2 |
| Softmax | — | 正确/错误 |

- 参数量约 2–4 万；int8 模型约 20–40KB。
- 训练：AdamW，学习率 1e-3，batch 16，100 epochs，early stopping；类别权重平衡。
- 评估：5 折按说话人交叉验证，报告 mean±std；AUC、F1、混淆矩阵。

### 6.4 量化与部署

1. PyTorch 训练 → 导出 ONNX。
2. ONNX → TFLite（或 Keras 复现）→ 全整型 int8 量化。
3. 代表性数据集 100–200 条，覆盖男女/正确错误。
4. 校准后检查准确率下降；若 >3%，做 QAT。
5. 生成 C 数组，放入固件；TFLite Micro interpreter。
6. Arena 约 30–60KB（内部 RAM）；输入/输出缓冲小。
7. 推理耗时用 `esp_timer` 测：预处理、推理、后处理分开记录。

> 备选：ESP-DL 可能更快，但工具链/算子支持需先验证；论文以 TFLite Micro 为主，ESP-DL 作为性能对照（可选）。

### 6.5 评价指标

- 分类：Accuracy、Precision、Recall、F1、AUROC、混淆矩阵。
- 一致性：与规则法的 Cohen's kappa；连续分数用 Pearson/Spearman。
- 部署：模型大小、arena、推理耗时（均值/最大）、量化精度损失。
- 公平性：按性别/说话人分组看准确率，讨论偏差。

## 7. 规则法对照

### 7.1 算法

1. 分帧 25ms/10ms，YIN/自相关提取 F0，范围 70–400Hz。
2.  voiced/unvoiced 判断；去掉静音段。
3. 与参考发音的 F0 轮廓做 DTW 对齐。
4. 特征：
   - 平均半音偏差（相对参考中位数归一化）。
   - 轮廓相关系数。
   - 时长比。
   - 能量比。
5. 在训练折上选阈值，输出 0–100 分 + 正确/错误。

### 7.2 对照实验

| 指标 | 模型法 | 规则法 |
| --- | --- | --- |
| Accuracy / F1 | 5 折 mean±std | 同折 |
| 与人工标签一致性 | kappa | kappa |
| 两法决策一致性 | — | Cohen's kappa |
| 分数相关性 | — | Pearson/Spearman |
| 推理耗时 | ms | ms |
| 模型/代码大小 | KB | KB |
| 对性别/口音敏感性 | 分组统计 | 分组统计 |

预期：模型法准确率更高但需数据；规则法可解释、耗时低，但对性别/口音更敏感。无论结果如何，如实报告。

## 8. 局部刷新与刷新策略

### 8.1 现状

- 4.2" HINK-E042A13-A0（SSD1619A）实测为**单色**：RED 平面测试第三块仍为白色。
- 只用 OTP/标准 `0x22` 时没有可用 partial LUT：9 种模式全部约 4 秒全刷；全刷实测约 4–6 秒。
- **使用 EPaperDrive 的 70 字节 partial LUT + MUX/gate start 后，已实现 70 行带状真局刷**：
  - 整屏底图：约 **700 ms**；
  - 70 行带状更新：约 **346 ms**；
  - 带状外完全不动；X 方向仍全宽，但整宽数据写入后横带不闪。
- 其他 LUT 结果：OSHWHub GaAs Full LUT 约 **2085 ms** 清晰全刷；GS LUT 450 ms 但很淡/残影。
- EPaperDrive 是 **AGPL-3.0**；LUT/序列仅用于本地验证，发布/商用需遵守 AGPL 或独立重写。

详见 [`局刷测试记录.md`](局刷测试记录.md)。

### 8.2 本方案的做法

1. 进入局刷模式：硬件复位，按 EPaperDrive 的初始化序列设置 `0x01/0x0C/0x3A/0x3B/0x3C/0x11/0x2C/0x37/0x21/0x22`，加载 70 字节 partial LUT。
2. 先用同一套 partial 初始化/LUT 画整屏底图（约 700 ms），不能与 OTP 全刷混用。
3. 页面变化时，设置 `0x01` MUX=69、`0x0F` gate start=95，再设置 `0x44/0x45/0x4E/0x4F` 窗口，写 `0x24`，`0x20` 更新（约 346 ms），带状外不动。
4. 每 20–30 次局刷执行一次“全白 → 全黑 → 底图”清洁周期（约 2.1 s），控制残影；页面大改时重画底图。
5. 备用：OTP 全刷（4–6 s）或 OSHWHub Full LUT（2.08 s）用于恢复/对照。
6. 论文中如实区分“OTP 全刷”“区域写 RAM”“partial LUT 全帧刷新”“MUX/gate start 带状真局刷”。

### 8.3 刷新策略

- 首页/页面切换：整屏底图 700 ms。
- 单词切换/进度变化：70 行带状局刷 346 ms；只扫该 70 行。
- 连续 50 次带状局刷：每次 346 ms，残影轻微、带状外基本不变；清洁后恢复。
- 清洁周期：每 20–30 次局刷执行“全白 → 全黑 → 底图”（3 × 709 ms，约 2.1 s），可完全恢复；对残影敏感可每 10 次。
- 50 词单词卡演示：布局 320×120，最终用 MUX + gate start 的 70 行带状局刷；序号 2 倍字体 + 单词 4 倍字体；每次 346 ms + 停留 1 s；第 25 次清洁一次。实测居中清晰、切换正常、带状外不动。
- 深睡前确保最后一次刷新完成。
- AGPL：若采用 EPaperDrive 的 LUT/序列，项目发布需遵守 AGPL-3.0，或从 datasheet 独立重写。
