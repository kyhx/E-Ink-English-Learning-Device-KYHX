# M2 测试记录（2026-10-26）

> 目标：把“录音 2 s → 存 WAV → VAD 裁剪 → 回放”的音频链路跑通，并给 M3 的规则法/采集工具留下稳定接口。
>
> 结论：**麦克风采集、WAV 写入、VAD、20 条连续录音文件完整性、PC 下载全部通过**；**功放/喇叭的声学回环未通过（录音里检测不到 1 kHz）**，因此 M2 的“回放清晰”门禁尚未闭合。代码、接线和排查步骤都已落地，见第 6 节。

## 2. 代码结构

| 文件 | 作用 |
| --- | --- |
| `main/services/audio_in.c/.h` | I2S0 RX 任务、PSRAM 缓冲、32→16 bit、增益、DC/削顶统计 |
| `main/services/audio_out.c/.h` | I2S1 TX、MAX98357A 使能时序、WAV/测试音播放、录放互锁 |
| `main/services/audio_wav.c/.h` | RIFF/WAVE 读写、录音目录/文件名、最近文件查找、临时时钟 |
| `main/services/audio_vad.c/.h` | 20 ms 帧/10 ms hop 能量 + ZCR、噪声底、端点裁剪 |
| `main/services/audio_analysis.c/.h` | RMS/峰值/DC/削顶、700–1300 Hz Goertzel 扫描、SNR |
| `main/services/audio.c/.h` | 初始化入口 + `audio_busy()` |
| `main/app_state.c` | RECORD 录音 UI、电平条、SAVED/NO SPEECH、PLAY 回放 |
| `main/bench/bench.c` | `bench audio ...` 验收命令 |
| `tools/audio/bench_audio.py` | 串口验收 + WAV 下载（修正了 `%04x` 大端文本到 WAV 小端的字节序） |

### 2.1 采集链

- I2S0 master RX，Philips 格式，32-bit 左对齐槽，单声道取左；INMP441/MS4030 的 24 bit 数据取高 16 bit（`raw >> 16`）。
- DMA 8 × 256 帧（约 128 ms 余量），采集任务固定在 core 1，UI 的 346 ms 带状刷新不会造成 I2S overrun。
- 上电后先丢弃 **100 ms**（`SETTLE_SAMPLES=1600`）：实测前 100 ms 有约 29k 峰值的上电/直流建立瞬态；不丢弃会被 VAD 误判为语音。
- 缓冲区加 100 ms 余量，但只保留请求的 2.0 s；返回 PCM 的所有权给调用者，由 `audio_in_free()` 释放。
- 统计：峰值、RMS、DC、削顶数、首样本延迟；增益在 Kconfig 中可调 50–400%。

### 2.2 播放链

- I2S1 master TX，16-bit **立体声**，单声道样本复制到 L/R（对 MAX98357A 更稳）。
- `AMP_SD=47` 高电平使能：播放前 10 ms 拉高，结束后 50 ms 拉低；前后各写 20 ms 静音，降低 pop。
- 录放互锁：录音时拒绝播放；播放时拒绝录音。全双工只用于一次性诊断，因 RX 停住已从固件移除。
- WAV 只接受 16 kHz/16 bit/mono 或 stereo；stereo 下混为 mono。ADPCM 资产解码留到 M5 的 `audio.pak`。

### 2.3 WAV 与文件名

- 44 B RIFF 头 + PCM16；2.0 s 文件 **64,044 B**。
- 目录 `/storage/rec`；文件名 `rec_YYYYmmdd_HHMMSS_mmm.wav`。
- 板上没有 RTC/SNTP，M2 用 `__DATE__/__TIME__` 播种一个临时时钟；真实时间在 M7 由 SNTP 或浏览器回传校正。日志会打印一条警告。
- 文件名精确到毫秒，连续录同一秒也不会覆盖。

### 2.4 VAD

- 20 ms 帧（320 点）/ 10 ms hop（160 点）。
- 噪声底 = 各帧能量 20 分位；语音阈值 = `max(噪声+8 dB, -55 dBFS)`。
- 首尾各保留 100 ms；有效语音 <300 ms 判“未检测到语音”。
- 额外要求平均 ZCR ≥0.008，避免把 50 Hz 电源/直流建立当成语音；实测安静房间从“speech=yes 660 ms”变为“speech=NO”。

## 4. 实测结果

### 4.1 算法自检（不依赖麦克风/喇叭）

`bench audio gen 500` 在设备内生成 1 kHz、幅度 6000 的 WAV，再用同一套 `audio_measure()` 分析：

```text
gen: /storage/rec/gen_1khz.wav, frames=8000
  expected: 1000 Hz, -14.7 dBFS
  measured: 1000 Hz, -17.8 dBFS, SNR=162.6 dB, rms=-17.8 dBFS, dc=0
```

> 期望值按峰值算应为 −14.7 dBFS；实测 −17.8 dBFS 是 **RMS**，对应 `6000/√2`，算法正确。表中保留原始日志，避免事后改数。

### 4.2 麦克风录音

`bench audio rec 2000`：

```text
captured: 32000 frames (2.0 s), start=121 ms
level: peak=1560 rms=246 dc=-14 clip=0 (0.00%)
tone:  0 Hz, 0.0 dBFS, SNR=0.0 dB
vad:   speech=NO 700 ms, noise=-68.9 dBFS, speech=-44.4 dBFS, SNR=24.4 dB
saved: /storage/rec/rec_20261026_121635_040.wav
```

- 帧数精确 32,000；无削顶；DC 很小。
- **start=121 ms**：其中 100 ms 是主动丢弃的稳定期，DMA/任务启动约 21 ms。门禁写的“<100 ms”按“首个可用样本”算未达标；按“命令响应/开始采集”算约 21 ms。这个取舍写进论文时要说明。
- 安静房间 VAD 正确判“NO”；真实人声未录（本轮没有真人说话），所以“20 条可懂”不能打勾。

### 4.3 连续 20 条

`bench audio soak 20`（每条 1000 ms，1 s 版本用于快速查文件完整性）：

```text
#00 frames=16000 clip=0 speech=NO 660 ms file=OK
...
#19 frames=16000 clip=0 speech=NO 250 ms file=OK
soak: 20/20 valid files
```

- 20/20 文件头、帧数、可读性通过；无削顶；每条 32,044 B。
- 移除 duplex 诊断后的最终固件又复测一次：**20/20**，20 条均 `speech=NO`（安静房间没有被误判为语音），`file=OK`。
- 之后 `bench audio list` 显示 25 个 WAV、约 860 KB，`storage free` 约 8.6 MB。
- 空间核算：100 条 2 s WAV = 100 × 64,044 B ≈ **6.1 MiB**，小于 10 MB 分区可用空间，满足“100 条 2 s 能存下”。

### 4.4 PC 下载

`tools/audio/bench_audio.py rec --ms 1000` 下载后：

```text
nchannels=1 sampwidth=2 framerate=16000 nframes=16000
peak=1681 rms=335.6
```

与设备端 `peak=1681 rms=331` 一致（RMS 差异来自 Python 未去 DC）。WAV 可直接用 Audacity/手机播放。

### 4.5 回放与声学测试（未通过）

- `bench audio play` 返回 `play: ok`，I2S 写入无错误；**没有听感确认**。
- 曾用 `bench audio loopback 1`（录音同时播 1 kHz/600 ms）测试：录 1.5 s，结果 0/1，录音里没有 1 kHz 成分，峰值只有环境级 1332，说明 **喇叭没有把声音送到麦克风**。
- 该 duplex 诊断还暴露了一个问题：I2S1 TX 与 I2S0 RX 同时开启时，RX 会停止供数，`bench` 可能卡在播放/等待；为避免把调试命令做成挂起命令，**已从固件移除 `loopback`**。生产路径本来就有录放互锁，不做全双工，不受影响。
- 正式声学测试改为按计划用手机播 1 kHz，然后 `bench audio rec 2000` + `bench audio analyze`；这样只开 RX，不会触发 duplex 问题。

已排除软件互锁、I2S 写失败（返回 ok）、单声道槽（已改 16-bit stereo 双写）。最可能的硬件原因，按优先级：

1. **MAX98357A 没有 5 V**：COM 口供电时 5V 排针默认是输入，需要桥接板背面的 `IN-OUT` 焊盘；功放只接 3.3 V 也能响但会小很多。
2. **SD/使能**：GPIO47 必须为高；若模块把 SD 当低有效，需要改极性或加反相。
3. **喇叭接法**：必须接在 +/− 差分输出，任一端接 GND 可能保护/无声；3 W 喇叭阻抗以实物为准。
4. **DIN/BCLK/LRC 接错**：DIN=21、BCLK=17、LRC=18，和 EPD 的 7–12 不冲突。

`bench audio selftest` 只覆盖“生成→写→读→启动录音”，它返回 PASS 不代表喇叭出声；声学门禁以手机 1 kHz + `analyze` 或人耳确认为准。

| 录音启动 <100 ms | **首个可用样本 121 ms**（含 100 ms 稳定丢弃）；DMA 启动约 21 ms |

| 电流粗测 | **未做**：INA219 尚未接入；M2 只记录“待 M7” |

补充：`app_state` 的 RECORD/PLAY 物理按键路径已实现，但本轮没有人工按键确认（M0 的 5 键物理按下也仍待确认），因此 UI 反馈只做了代码审查，未做按键实测。

结论：**M2 的软件/存储/VAD/下载部分完成，声学门禁未闭合**。在功放修好前不把 M2 标成完全完成，也不拿“selftest PASS”冒充“回放清晰”。
