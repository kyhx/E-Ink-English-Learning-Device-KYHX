# SSD1619A “完全真局部”研究记录

> 日期：2026-10-25
> 屏幕：HINK-E042A13-A0，SSD1619A，4.2" 单色 400×300
> 相关代码：`epd_band_update()`、`main.c` 50 词演示

---

## 1. “完全真局部”要先定义

| 层次 | 含义 | 当前是否做到 |
| --- | --- | --- |
| **视觉/像素级** | 只有目标矩形内的像素发生翻转；矩形外画面完全不动、不闪 | **做到** |
| **驱动级** | 只有目标矩形内的像素被施加驱动波形；其他像素不驱动 | **做到**（未变化像素 WW/BB 不驱动） |
| **扫描级（Y）** | 只扫描目标矩形所在的 gate 行 | **做到**：MUX + gate start 只扫 70 行 |
| **扫描级（2D）** | 只扫描目标矩形的 gate 行 + 只驱动目标列的 source | **做不到**：SSD1619A 没有 source X 窗口 |

所以“完全真局部”如果指**视觉/像素级**，当前已经做到；
如果指**任意 2D 扫描窗口**，SSD1619A 硬件做不到。

---

## 2. datasheet 依据

SSD1619A：

- 400 source outputs，300 gate outputs；
- `0x01` Driver Output Control：MUX（16..300）、GD/SM/TB；
- `0x0F` Gate Scan Start Position：起始 gate（0..299）；
- `0x44/0x45`：只设置 **RAM 写入窗口**；
- `0x21`：只选择 RAM 内容（Normal/Bypass/Inverse）；
- `0x22`：只有 clock/analog/display/LUT 组合序列，**没有 partial window 位**；
- 没有 source X start/end 或 source output disable 命令。

结论：

> **能限制 Y（gate）扫描，不能限制 X（source）输出。**
> 任意 2D 扫描窗口在 SSD1619A 上不存在。

---

## 3. 实验对比

| 方案 | 时间 | 视觉 | 扫描范围 | 结论 |
| --- | --- | --- | --- | --- |
| OTP 全刷 | 4–6 s | 全屏闪 | 300 行 × 400 列 | 基线 |
| 400×300 全帧 transition-only | 739 ms | 无可见闪 | 300 行 × 400 列 | 只驱动变化像素，但不省 gate 扫描 |
| 128×70 数据窗口 | 684 ms | 横带/框外闪 | 300 行 × 400 列 | 只限数据，不限扫描 |
| MUX 70 行 + 128px 数据 | 351 ms | 横带闪（文字框内不闪） | 70 行 × 400 列 | Y 局部扫描成立，但横带左右无新数据 |
| **MUX 70 行 + 整宽 400px 数据** | **346 ms** | **横带不闪，只有文字变化** | **70 行 × 400 列（像素只驱动文字）** | **当前最终方案** |

### 关键发现

只写 128px 宽时，横带左右两侧没有新数据，LUT 仍会驱动/闪；
写整条 400px 宽后，未变化像素走 WW/BB 不驱动，横带就不闪了。

因此当前方案是：

> **70 行 gate 扫描 + 整宽 source 数据 + transition-only LUT**
> = 视觉/像素级 2D 真局部；扫描级 Y 局部、X 全宽。

---

## 4. 为什么不能做“只扫 128 列”

SSD1619A 的 source 输出固定 400 路，只有：

- RAM X 窗口（`0x44`）限制**写 RAM 的列**；
- 没有 source output enable/disable 或 X 扫描范围寄存器。

即使只写 128 列，source 输出仍会驱动整行 400 列，导致横带闪。
写整宽数据是让“未变化列不驱动”的唯一办法。

---

## 5. 当前能给出的最强结论

> **SSD1619A + 这块 HINK 屏，可以做到“视觉/像素级 2D 真局部”，但不能做到“扫描级 2D 窗口”。**
>
> - 视觉：只有单词/序号变化，带状外完全不动，横带不闪；
> - 扫描：只扫 70 行 gate；X 仍 400 列；
> - 时间：346 ms/词；
> - 限制：不是任意矩形窗口；X 方向没有源窗口。

如果论文/验收要求“只扫描任意矩形（行列都局部）”，需要换控制器/屏，或拿到支持 source window 的驱动方案；当前 SSD1619A 固件无法做到。

---

## 6. 还可以继续研究的方向

1. **带状窗口位置**：把 gate start 改到不同 y，验证任意 Y 位置都能带状局刷；
2. **更窄的带**：把序号和单词压到同一行，带高从 70 降到 35–40 行，进一步减少扫描；
3. **双带**：序号一条小带 + 单词一条小带，分别刷新；时间可能接近，但视觉更局部；
4. **功耗实测**：346 ms × 70 行 vs 739 ms × 300 行，测 gate/source 能耗；
5. **长期可靠性**：MUX 70/300 反复切换对 gate driver 的影响；
6. **温度**：不同温度下 70 行波形的对比度/残影。

---

## 7. 一句话

**当前已经是 SSD1619A 上能做到的“最强真局部”：70 行带状扫描、整宽数据、346 ms、带状外不动、横带不闪。再往上只能是“任意 2D 扫描窗口”，这需要换硬件，不是继续调 LUT 能解决的。**
