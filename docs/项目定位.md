# 项目定位与优先级（2026-11-03）

## 0. 一句话

> **首要目标：就业；必须目标：完成本科毕业设计。**
> 技术定位：**端侧 AI（TinyML）工程实践**，不追求算法理论创新。

这个项目不是“做一个完美的学习机”，而是：

1. 产出一份能拿去面试的**工程作品**；
2. 产出一篇能满足学校要求的**毕业设计**。

---

## 1. 两个目标怎么排

| 优先级 | 目标 | 判断标准 |
| --- | --- | --- |
| P0 | 毕业 | 学校硬性要求满足；论文可复现；能答辩 |
| P1 | 就业 | 有自绘 PCB、TFLM 闭环、实测数据、可展示仓库 |
| P2 | 产品化 | 外壳、认证、量产、Wi-Fi 同步等，能砍则砍 |

**冲突时：先保毕业，再保就业证据；两者都不违背才做产品化。**

---

## 2. 技术定位

准确说法：

> 面向英语单词跟读的**端侧 AI 工程实践**：在 ESP32-S3 的存储、算力、功耗约束下，完成“录音 → VAD → log-Mel → int8 模型 → 墨水屏结果”的离线闭环。

不准确、不要作为主要卖点：

- “边缘计算创新”；
- “机器学习算法创新”；
- “首次将 AI 用于学习机”；
- “高准确率发音评测”。

创新点应落在：

1. **词条件化**的轻量发音判别；
2. **11.5 KB int8 模型 + TFLM** 的端侧部署；
3. **346 ms 带状局刷 + 离线交互** 的系统协同；
4. **设备自采数据 + 说话人独立评估**。

---

## 3. 就业交付物

面试时能拿出来的东西：

| 交付物 | 最低要求 | 价值 |
| --- | --- | --- |
| 自绘 PCB | 4 层，ESP32-S3 + EPD + 音频 + 电源 | 硬件岗核心证据 |
| TFLM 闭环 | 录音→Mel→推理→结果页 | 嵌入式/端侧 AI 核心证据 |
| 实测报告 | 延迟、RAM、Flash、电流、刷新 | 区分“做过”和“做好” |
| GitHub 仓库 | README、图、BOM、测试记录 | 可展示、可复现 |
| 演示视频 | 1–2 分钟 | 面试/简历链接 |
| 实习 | 越早越好 | 比再加功能更重要 |

---

## 4. 毕设最低交付

| 项 | 最低 | 目标 |
| --- | --- | --- |
| 词库 | 50 词 | 100 词 |
| 数据 | 200 条，说话人独立 | 600 条 |
| 模型 | int8 轻量 CNN，TFLM 上板 | 词条件化 |
| 对照 | 规则法/PC 参考 | 三方对照 |
| 指标 | 准确率、kappa、耗时、功耗 | 消融/置信区间 |
| 论文 | 结构完整、数据可复现 | 有工程贡献表述 |

---

## 5. 可砍 / 不可砍

### 可以砍或延后

- 4.26" 480×800 新屏；
- Wi-Fi/SoftAP 同步；
- 外壳/注塑/认证；
- OpenPronounce 深度使用；
- 600 条扩到 800 条；
- 双人标注降为单人 + 抽查；
- 复杂消融实验。

### 不能砍

- TFLM 端到端闭环；
- 200 条设备自采数据 + 说话人独立划分；
- 规则法/PC 参考对照；
- 刷新/推理/功耗实测；
- 论文与答辩材料；
- 自绘 PCB（就业核心）。

---

## 6. 决策规则

每加一个功能，先问三句：

1. 它是否直接增加就业证据？
2. 它是否阻塞毕业？
3. 它是否能在一周内做完并量化？

答“否”的，降级为可选或不做。

---

## 7. 推荐时间分配

```text
TFLM + 结果页         30%
自绘 PCB + 电源/音频   30%
测试/数据/论文         25%
简历/投递/面试         15%
```

不要把所有时间花在“再调一点准确率”或“再换一块屏”上。
