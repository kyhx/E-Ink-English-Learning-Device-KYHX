## 1. 屏与控制器

| 项 | 值 |
| --- | --- |
| 模块型号 | ZJY128296-029EAAMFGN（中景园 2.9"） |
| 控制器 | **SSD1680** |
| 分辨率 | **128 × 296**（竖屏） |
| 颜色 | 黑白（1bpp） |
| 接口 | 4 线 SPI（CS/DC/RST/BUSY + SCK/MOSI） |
| 帧大小 | 16 B/行 × 296 行 = **4736 B** |
| 可视面积 | 37,888 px²，约为 4.2" 400×300 的 **31.6%** |

## 2. 与 4.2" SSD1619A 的关键差别（这也是换屏最大的收益）

| 项 | SSD1619A 4.2" | SSD1680 2.9" |
| --- | --- | --- |
| 局刷能力 | 只能 **70 行带状**（MUX + gate start 技巧，X 全宽） | **任意矩形窗口**（0x44/0x45 真窗口） |
| 局刷机理 | 全屏扫描但只改带内 | BW RAM（新）与 RED RAM（旧）逐像素比较 |
| 局刷耗时 | 346 ms（70 行） | 待实测（预计 200–400 ms，与窗口面积相关） |
| 全刷耗时 | 709 ms | 待实测（预计 1.5–2 s） |
| 面积 | 400×300 | 128×296（明显小） |

**结论方向**：SSD1680 的“任意矩形局刷”在技术上更漂亮，论文里“真局部刷新”不用再解释带状限制；代价是屏小、单词卡要重新排版。

## 3. 接线

沿用现有 4.2" 驱动板 V1.5 的 6 根线，**不需要改线**（引脚在 `main/board/board_pins.h`）：

| 信号 | GPIO | 2.9" FPC 常见脚位 |
| --- | --- | --- |
| BUSY | 7 | BUSY |
| RST | 8 | RES# |
| DC | 9 | D/C# |
| CS | 10 | CS# |
| MOSI | 11 | SDI/DIN |
| SCK | 12 | SCLK |
| 3.3V | 3V3 | VDD/VCC |
| GND | GND | GND/VSS |

注意事项：

1. 2.9" 模块通常 **3.3 V 逻辑和 3.3 V 面板供电**，不要接 5 V。
2. 有些 8 pin FPC 多一根 **BS1**（SPI/4 线模式选择），按模块丝印接 GND 或悬空；若屏完全不响应，先查这根。
3. FPC 金手指方向与 4.2" 不同，**插反会全白且 BUSY 常高**——先用万用表量 VDD/GND 是否短路。

## 9. 故障对照表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 全白，BUSY 一直高 | 排线插反/虚接；BS1 未接；3.3 V 没到 | 量 VDD/GND；重插 FPC；查 BS1 |
| 全白，`init ok=1` 但屏无反应 | SPI 模式/极性；CS 未拉低 | 逻辑分析仪看 SCK/MOSI；确认 CS 常低到事务结束 |
| 全黑（该白的地方黑） | 位极性相反 | `bench epd1680 invert 1`，固化到 `epd1680_set_invert(true)` |
| 图像上下颠倒 | 0x01 的 TB 位 | 把 `0x01` 第三字节 0x00 改 0x08 |
| 图像左右镜像 | 0x11 数据递增方向 | 0x03 → 0x02（X 减 Y 增）或配合窗口反向 |
| 局刷不生效（和全刷一样慢/闪） | 0x22 模式值不对；RED 基准未建立 | 先做一次全刷再局刷；试 `0x22` 用 `0xCF`/`0x0F` |
| 局刷后整屏发灰 | RED RAM 基准没跟上 | 检查 `epd1680_partial()` 末尾的 RED 回写是否执行 |
| 残影明显 | 局刷次数过多 | 每 20–30 次局刷插一次全刷 |
| 文字有横向错位 | 窗口 x 不是 8 的倍数 | x/w 必须 8 的倍数 |

## 10. 协议依据与已知不确定性

驱动实现在 `components/epd_ssd1680/`，刷新流程按 SSD1680 datasheet 的 `0x21/0x22/0x24/0x26/0x44/0x45/0x4E/0x4F` 寄存器语义实现，`0x22` 组合值沿用 Linux DRM `ssd16xx` 驱动对 SSD1680/SSD1683 的定义：

| 模式 | 0x21 | 0x22 | 说明 |
| --- | --- | --- | --- |
| 全刷 | 0x40,0x00（bypass RED） | **0xF7** | 载温度 + 载 LUT + 显示 |
| 快刷 | 0x40,0x00 | **0xC7** | 不载 LUT（init 时预载） |
| 局刷 | 0x00,0x00（用 RED 作基准） | **0xFF** | Display Mode 2 |

**未验证项（第一次上板时重点看）**：

1. `0x22` 的局刷值是不是 `0xFF`——不同 SSD1680 固件版本/OTP LUT 可能只支持 `0xCF` 或 `0x0F`。
2. 快刷 `0xC7` 是否真的比全刷快（有些模组 OTP 里没有独立 fast LUT）。
3. 位极性是否 1=白（4.2" 的 SSD1619A 是 1=白，SSD1680 多数也是，但不保证）。
4. `0x18 = 0x80`（内部温度传感器）是否被模组支持。

以上 4 条任一条不成立，只影响参数，不影响结构——都在第 9 节有对应处理。
