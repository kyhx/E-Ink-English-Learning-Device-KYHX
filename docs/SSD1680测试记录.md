## 1. 屏与控制器

| 项 | 值 |
| --- | --- |
| 模块型号 | ZJY128296-029EAAMFGN（中景园 2.9"） |
| 控制器 | **SSD1680** |
| 分辨率 | **128 × 296**（竖屏） |
| 颜色 | 黑白（1bpp） |
| 接口 | 4 线 SPI（CS/DC/RST/BUSY + SCK/MOSI） |
| 帧大小 | 16 B/行 × 296 行 = **4736 B** |
| 可视面积 | 37,888 px²，约为 4.2" 400×300 的 **31.6%** |

## 2. 实测结果（2026-11-05，实机）

| 项目 | 实测 | 备注 |
| --- | --- | --- |
| 初始化 | **53 ms** | 含硬复位 + 软复位 + 参数下发 |
| 全刷 全白 (0xF7) | **2024 ms** | |
| 全刷 全黑 (0xF7) | **2023 ms** | |
| 全刷 图案 (0xF7) | **2023 ms** | |
| 局刷 8×8 (0xFF) | **449 ms** | |
| 局刷 64×24 (0xFF) | **451 ms** | |
| 局刷 128×32 (0xFF) | **450–451 ms** | |
| 局刷 128×96 (0xFF) | **455 ms** | |
| 局刷 128×296 整屏 (0xFF) | **468–469 ms** | 相当于“全屏快刷” |
| 0xC7“不载 LUT”模式 | 463 / 2018 ms **跳变** | **弃用**，见 2.2 |

重复性：同一命令连跑 2–5 次，偏差 ≤2 ms；全刷 3 次 2023/2023/2024 ms。

### 2.1 关键发现：局刷耗时与窗口面积基本无关

8×8 的窗口 449 ms，整屏 128×296 的窗口 468 ms，**只差 19 ms**。

原因：SSD1680 的刷新波形总是扫描全部 296 条 gate，`0x44/0x45` 窗口只限制**写入 RAM 的数据量**，不限制扫描行数。窗口越小，省下的是 SPI 传输时间（4 MHz 下整帧 4736 B ≈ 9.5 ms），不是波形时间。

> 论文里必须写清楚这点，否则会被问“为什么 8×8 也要 450 ms”。正确表述是：
> **局刷成本 ≈ 波形固定开销（≈450 ms）+ 数据量/SPI 速率**，与窗口面积弱相关。

### 2.2 0xC7 为什么弃用

`0x22 = 0xC7` 的含义是“不重新载入 LUT”。实测：

| 前一条命令 | 紧随其后的 0xC7 耗时 |
| --- | --- |
| 全刷 0xF7（已载入全刷 LUT） | **2018 ms** |
| 局刷 0xFF（残留局刷 LUT） | **463 ms** |

即 0xC7 的波形取决于上一条命令残留的 LUT，不可作为稳定接口。现已把 `epd1680_fast()` 改为**整屏局刷**（468 ms，行为确定），0xC7 不再对外暴露。

## 3. 与 4.2" SSD1619A 的对比（都很关键）

| 项 | SSD1619A 4.2" 400×300 | SSD1680 2.9" 128×296 |
| --- | --- | --- |
| 全刷 | **709 ms** | 2023 ms（慢 2.9×） |
| 局刷 | 346 ms（仅 70 行带状） | 450 ms（**任意矩形**） |
| 整屏“快速更新” | 709 ms（只能全刷） | **468 ms**（整屏局刷） |
| 面积 | 120,000 px² | 37,888 px²（31.6%） |
| 残影 | 带状局刷较干净 | 局刷累积残影，需定期全刷 |

**结论修正**：2.9" 不是“更快”，而是**刷新自由度更高**——任意矩形、且整屏局刷比 4.2" 全刷快 1.5 倍。但单次全刷慢 2.9 倍、面积只有三分之一。论文里应写成“窗口自由度 vs 面积/全刷速度”的权衡，不能只说“更好”。

若第 1/2 项反色 → `bench epd1680 invert 1` 后重画。
若第 3 项上下颠倒 → `0x01` 第三字节 0x00 改 0x08。
若第 5 项窗口外有变化 → RED RAM 基准未生效，检查 `epd1680_partial()` 末尾回写。

## 9. 故障对照表

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 全白且 BUSY 常高 | 排线插反/虚接；BS1 未接；3.3 V 未到 | 量 VDD/GND；重插 FPC |
| `init ok=1` 但屏无反应 | SPI 极性；CS 未覆盖整个事务 | 逻辑分析仪看 SCK/MOSI/CS |
| 该白的地方黑 | 位极性相反 | `bench epd1680 invert 1` |
| 图像上下颠倒 | 0x01 的 TB 位 | 第三字节 0x00 → 0x08 |
| 图像左右镜像 | 0x11 递增方向 | 0x03 → 0x02，配合窗口反向 |
| 局刷后整屏发灰 | RED 基准没跟上 | 检查局刷末尾 RED 回写 |
| 残影明显 | 局刷次数过多 | 每 20–30 次插一次全刷 |
| 文字横向错位 | 窗口 x 非 8 倍数 | x/w 必须 8 的倍数 |

## 10. 协议依据

实现在 `components/epd_ssd1680/`，按 SSD1680 datasheet 的 `0x21/0x22/0x24/0x26/0x44/0x45/0x4E/0x4F` 语义实现；`0x22` 组合值对照 Linux DRM `ssd16xx` 驱动对 SSD1680/1683 的定义：

| 模式 | 0x21 | 0x22 | 实测 |
| --- | --- | --- | --- |
| 全刷 | 0x40,0x00（bypass RED） | **0xF7** | 2023 ms |
| 局刷 | 0x00,0x00（RED 作基准） | **0xFF** | 450–469 ms |
| 快刷 | 0x40,0x00 | 0xC7 | 不稳定，弃用 |

已确认可用：内部温度传感器 `0x18=0x80`、边框跟随 VCOM `0x3C=0x80`、深睡 `0x10=0x01`（深睡电流未测）。
